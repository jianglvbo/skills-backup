# 模板写作指引

> 模板 = 纯结构骨架（字段骨架 + section 标题 + 表格表头），**不含任何解释**。本文件是模板各 section 的写作指引唯一真相源，提炼/创建条目时按此处指引填充。
> 模板与规则的分工：结构 → `assets/*.md`；写作要求 → 本文件；字段/标签/来源/脚注等全局规则 → framework-rules.md / tag-taxonomy.md / footnote-taxonomy.md。

## 通用约定（所有模板）

- **frontmatter 只写值，不留注释**：`star: false`、`delete:`（空）、`tags: []`、`source: []` 均为合法形态；字段含义与 canonical 顺序见 framework-rules #27
- **source 字段**：内部来源 wikilink / 外部来源 markdown 链接，二选一，见 framework-rules #23（链式引用：wiki 层指向原始资源，原始资源指向 URL）
- **tags 字段**：从 tag-taxonomy 选用，不自造标签；层级硬约束（≥2 级，禁裸标签）
- **脚注**：提炼阶段可加 `[^data-N]`（数据溯源）/ `[^date-N]`（时效标注）；关联脚注仅审查阶段添加；格式见 footnote-taxonomy
- **可读性优先**（framework-rules #18）：保留原文比喻、案例、推理链条；一句话核心判断、适用条件/边界、反直觉点、时间敏感性
- **段落布局**（framework-rules #33）：标题前后空行、段落间空行、禁止同行标题
- **空结构合法**：产出文件可保留模板的空 section 标题和空表格表头（如结果跟踪表暂无数据），但**不留全空占位行**（`| | | | |`）

## 个股（assets/个股.md）

- **用途**：个股信息枢纽条目，汇集用户与多博主对该股的分析
- **frontmatter**：标准 8 字段；`title` = 个股名称
- **文件名**：`{名称}({代码})`，代码确定优先级见 framework-rules #28
- **基本信息**：公司概况、主营业务、核心财务数据；不同维度分段写；财务数据加 `[^data-N]` 标注来源和截止日期
- **分析汇总**：汇集用户分析和多博主分析；保留各方分析的推理过程和关键判断，不简化为要点；不同来源/视角分段写
- **宏观影响**：影响该股的宏观事件，wikilink 到宏观文件；保留原文传导逻辑

## 宏观（assets/宏观.md）

- **用途**：宏观事件分析条目；顶层 `宏观/` 存通用框架，归属层下 `宏观/` 存具体来源的分析（framework-rules #7）
- **frontmatter**：宏观事件型顺序 `title → event → 时效状态 → 时间范围 → createDate → updateDate → author → star → delete → tags → source`
  - `event`：事件名称，用于跨博主聚合（如 `美联储加息周期`）
  - `时效状态`：进行中 / 已结束 / 已失效
  - `时间范围`：如 `2026年Q1-Q3`
- **事件概述**：背景、起因、核心内容；保留叙事逻辑和关键数据；引用数据用 `[^data-N]`，时间敏感判断用 `[^date-N]`
- **影响分析**：对市场和投资的影响判断；保留分析推理链条和案例
- **传导路径**：影响哪些行业、哪些个股，wikilink；保留传导逻辑

## 分析框架-方法论（assets/分析框架-方法论.md）

- **用途**：分析方法本身（如"用 PE 判断企业是否值得买入"）；与「分析档案」（应用实例）区分见 framework-rules「分析框架内部：方法论 vs 分析档案」
- **目录规则**：仅博主层方法论设 `方法论/` 子目录；我的/其他层直接用本模板不设子文件夹（framework-rules #11）
- **适用场景**：这个方法解决什么问题、什么情况下使用
- **方法步骤**：分析方法的步骤；保留原文讲解方式和具体案例，展示推理过程；不同步骤分段写，关键判断**加粗**
- **关键指标**：关注的核心指标和判断标准
- **案例**：用这个方法分析过的标的，wikilink 到分析档案；保留原文案例描述

---

## 分析框架-分析档案（assets/分析框架-分析档案.md）

- **用途**：用某方法论分析具体标的的实例（如"段永平用 PE 方法分析茅台"）；通过 wikilink 关联回方法论
- **frontmatter**：分析档案顺序 `title → 标的 → createDate → updateDate → author → star → delete → status → tags → source`
  - `标的`：股票名/代码
  - `status`：分析中 / 已决策 / 已建仓 / 已清仓
- **使用的方法论**：wikilink 到对应方法论文件
- **核心结论**：分析的最终判断；保留原文表述方式
- **分析过程**：完整的分析推理链条；保留推理步骤、数据引用和案例对比；不同步骤分段写，关键判断**加粗**；引用数据用 `[^data-N]`
- **估值判断**：估值层面的判断和依据
- **决策**：最终的操作决策和理由
- **结果跟踪**：表格记录后续市场表现验证（日期 | 事件 | 结果 | 当初判断是否验证）；无数据时保留表头即可

## 交易体系（assets/交易体系.md）

- **用途**：具体买卖条件、执行规则（操作手册）；与「分析框架」（工具箱）区分见 framework-rules「分析框架 vs 交易体系」
- **规则**：交易规则核心内容；保留原文表述方式，特别是形象化说法；不同规则要点分段写
- **适用条件**：什么时候用、什么情况下不用；保留原文条件判断逻辑和案例
- **验证记录**：如有后续市场表现验证了该规则，记录在此

---

## 投资心得（assets/投资心得.md）

- **用途**：有借鉴意义的经验教训；与「投资心态」（根因是情绪/心理）区分见 framework-rules「投资心态 vs 投资心得」
- **背景**：心得的来源背景——什么市场、什么事件、什么决策；标注时间背景和市场环境，帮助判断是否仍适用；不同论点分段写，关键概念**加粗**
- **经验教训**：原文的核心经验；保留推理链条和具体案例；比喻和生动表达一并保留；如有反直觉点（"大家以为 X，其实是 Y"）在开头拎出来；引用数据用 `[^data-N]`，时间敏感判断用 `[^date-N]`
- **借鉴意义**：这个心得怎么用、适用什么场景；从原文推导不编撰；**显式标出适用条件和边界**——什么情况下成立、什么情况下不成立；不同适用场景分段说明

---

## 投资心态（assets/投资心态.md）

- **用途**：心态问题/教训条目；根因是情绪/心理的归此（framework-rules「投资心态 vs 投资心得」）
- **场景**：触发这种心态的市场环境或具体情境；保留原文的比喻和场景描写；标注是哪个市场阶段触发
- **问题**：心态层面出了什么问题、原文怎么表达；保留生动比喻；如有反直觉点（如"越努力越亏钱"）拎出来
- **根因**：情绪/心理层面的根源分析；保留推理链条，展示从现象到根因的逻辑
- **应对策略**：原文提出的具体做法或建议；经验总结保留原文表述；不同策略分段写

## 行业（assets/行业.md）

- **用途**：行业分析条目；行业不按市场分文件夹，用标签区分（framework-rules #8）
- **行业概况**：行业基本情况、市场格局；保留原文描述和数据；如有核心认知冲突（市场共识 vs 实际情况）在开头点明
- **关键数据**：行业核心指标、周期性数据点；标注数据截止日期帮助判断时效；引用数据用 `[^data-N]`
- **时间线**：表格记录（时间 | 事件/数据 | 涉及个股，个股 wikilink）

---

## 博主（assets/博主.md）

- **用途**：已登记博主档案条目；仅博主控制台已登记博主可建（framework-rules #12）；**frontmatter 仅 7 个笔记属性字段**（title/platform/special_following/summary/info_cutoff/createDate/updateDate，见 #36），无 star/delete/tags/source
- **擅长与局限**：能力圈（具体领域、方法、标的类型）+ 盲区/风险点
- **言论追踪**：博主零散发言中敏锐的观点性言论；4 个 `###` 子表分类见 framework-rules #30（具象化/观点/信号/互动）；时间倒序；原文链接必填真实 URL
- **个股买卖**：博主明确买卖动作；操作枚举/价格取值/备注规则见 framework-rules #31；时间倒序
- **预测（准确率追踪）**：预测内容 | 时间 | 状态（已验证/验证中/待验证/证伪）| 原文链接，见 framework-rules #35
- 三表原文链接**禁止留空 `-`**；无来源帖链接则该行不建（framework-rules #35）
