# 任务格式细则（assign-tasks）

任务 = title（看板行上显示）+ content（MD 详情，点行展开）。看板对 content 做 Markdown 渲染，
四段标题用 `##`，步骤用编号列表，链接用 `[文字](url)`。

## 模板

```markdown
## 背景
<哪个环节（采集/粗加工/提炼/审查/其他）、遇到什么问题、为什么必须用户出手。2-3 句，给到能独立看懂。>

## 要你做的
1. <步骤一：具体到对象与动作>
2. <步骤二（可选）>

## 依据
- <言论/帖子/审查记录：有 url 的写 `[原文](url)`，只有 id 的写 `言论 #1234`>
- <相关规则或批次号（如「refine 批次 2026-09-28」「framework-rules #53」）>

## 期限
<有后果才写：「阻塞 10-01 提炼批次收尾」；没有就整段删掉，不写「尽快」。>
```

## 正反例

### 例 1：提炼遇到需要用户补资料的事

❌ 不合格（没说做什么、没依据）：
> title：`关于寒武纪的问题`
> content：`提炼时发现有问题，请处理。`

✅ 合格：
> title：`确认「讯狗」是否指寒武纪并补进别名`
> priority：normal　contextRef：`stmt:2456`
> content：
> ```
> ## 背景
> 提炼 09-29 批次时，metalslime 帖子提到「讯狗」，指标未建档、问财也解析不出，
> 该条言论的标的关联被挂空，影响言论追踪的个股维度统计。
>
> ## 要你做的
> 1. 确认「讯狗」= 寒武纪（688256.SH）
> 2. 若确认，回复本任务即可，下批提炼会由 agent 走 stock_alias 落库
>
> ## 依据
> - [原帖](https://xueqiu.com/…) · 言论 #2456
> - framework-rules #49（标的名解析不出）
> ```

### 例 2：审查发现需要用户拍板后执行一串修复

❌ 不合格（其实是问句，该走待决策）：
> title：`存量预测要不要清理`
> content：`## 背景\n发现一批旧预测……要不要清？`

✅ 合格（用户拍板后还要执行 SQL+重算，是动作不是答案）：
> title：`批准清理 2025 年前的 47 条僵尸预测`
> priority：high　contextRef：`review:2026-09-27`
> content：
> ```
> ## 背景
> 09-27 审查发现 47 条预测停在 pending 超一年、原标的已退市/改名，占着控制台待验证数。
> 审查裁决 #1782 你已同意清理，本任务＝执行清理。
>
> ## 要你做的
> 1. 核对清单（见依据的审查记录），确认无误
> 2. 在本任务回复「执行」，agent 下批收尾时按清单置 cancelled 并重算统计
>
> ## 依据
> - 审查记录 2026-09-27 · 待决策 #1782
> ```

### 例 3：线下/数据补录类

✅ 合格：
> title：`补录 WorkBuddy 池子月度对账数字`
> priority：low　contextRef：`file:工作区/对账/2026-09.md`
> content：
> ```
> ## 背景
> 09 月对账页里「实际余额」两格空着，粗加工时无法核对差异。
>
> ## 要你做的
> 1. 从银行导出 09-30 余额，填进对账页
>
> ## 依据
> - 对账文件 `工作区/对账/2026-09.md`
> ```

## 字段速查（note_item add）

| 参数 | 要求 |
|:---|:---|
| type | 固定 `task` |
| source | 固定 `agent` |
| raisedBy | 当前模型名短名（harness 的 model 标识） |
| title | 祈使句、动词开头、≤30 字、不带句号 |
| priority | high=阻塞流水线 / normal=今天内 / low=可延后；缺省 normal |
| dueDate | 可空；有明确期限才填 yyyy-MM-dd |
| contextRef | 必填，格式 `stmt:` / `pending:` / `post:` / `review:` / `file:` |
