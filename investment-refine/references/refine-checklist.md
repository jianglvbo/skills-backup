> 适用对象：xueqiu-spyder 采集并已落 `post_history` 的博主帖子集（2026-09-12 起从库内原文直接提炼，不再有 vault 粗制品文件）。
> 权威规则：`framework-rules.md` #29（帖子集例外流程）。本清单是 #29 的执行版，提炼前必加载、逐条照做。
> 本清单由 xueqiu-spyder 采集完成后、交给 investment-refine 执行，采集阶段不分析内容（遵守 SKILL.md 禁止行为）。

## 0. 例外流程（与常规流水线不同；2026-09-12 改为「从 post_history 直提」）
- **原文来源＝`post_history` 库内原文**（采集时已直接落库，规则 #41）：用 MCP `post_history` `action=get`（单帖全文）/`action=check`（按博主+时间窗列清单）读取，**不进原始资源、不置 `status=待提炼`、不读也不产生 vault 文件**。
- 采集产物 md 是临时文件，落库 + 入库校验通过后已清理；**没有需要移入废纸篓的源文件**。
- 框架条目 `source` 写**雪球原文帖子链接**（例：`[标题（博主 日期）](https://xueqiu.com/.../XXXXXX)`，取自本批次该帖的 `[原文]` 链接），**禁止用采集批次文件名**（批次删后不可追溯），避免悬空引用。

## 1. 逐条价值流水线（对每条帖子）
1. **判信息量**：纯情绪 / 调侃 / 段子 / 水帖 → 直接丢（糟粕）。
2. **判具象化**：有信息量且能落成分析框架 / 交易体系 / 投资心得 / 行业等方法论或认知 → **生成框架文件**（精华落地）。
3. **判留存**：不能具象、但观点有留存价值 → 进博主画像「言论追踪」对应子表（具象化 / 观点 / 信号 / 互动）。
4. **判增量**：对已有条目的补充 → 追加进现有文件，不新建重复条目。

## 2. 灰区裁决（拿不准时按此办）
- **有时效但藏框架/理由**（如"今天减仓"）：拆——具体动作/买卖点位/时点删，框架理由留；若框架理由能具象成分析框架文件，判价值，有价值则留。
- **互动/回复类**（博主常回别人）：只取博主**原创观点**，被回复者话当上下文不提炼；能具象成文件的才生成文件，有留存价值的存入言论追踪。
  - **引用结构切分（`//@` 链 + 转帖引用卡；2026-09-09 固化，硬约束）**：博主原话与被引内容的边界按两种结构判定——
  - ① **行内 `//@` 链**：雪球原生行内嵌套引用格式为 `博主原创…//@被引用者:被引用内容`。**`//@` 之前是博主原创（提炼对象）**，`//@` 之后是被回应者的话；**多重嵌套只取第一个 `//@` 之前**。
  - ② **转帖引用卡**（2026-09-26 feed 模式新增；三种载体：帖子集的「回复内容·专栏/·原帖」块、详情页来源正文尾部的内联「@作者：…」卡片段）：被引**专栏** → `replyTo` 取《文章标题》（导语是采集截断、只作语境）；被引**原帖** → 卡内被引文本照抄进 `replyTo`；**卡片尾注（时间/转发/讨论/赞）与卡片正文不得混入博主 `view`**。字段语义与去包装细则 → refine-schema.md「引用结构切分落位」。
    - **格式变体（三种都要认）**：`//@某人:`、`//[@某人]:`、`//[@某人](https://xueqiu.com/n/某人):`
    - **切分后须剥离标注前缀**：正文开头的 `回复@某人:` / `回复[@某人](url):` 是回复对象标注、非内容，**剥离后再提炼**；`//@` 之后同样剥离嵌套的 `回复@某人:` 前缀（**2026-09-12 规则 v3：`replyTo` 只存剥完包装的对方原话本身**——`//@昵称：` 署名与嵌套 `回复@昵称:` 都不进字段，说话人昵称也不进；用户原话见 framework-rules #46）
    - 标题同样适用：取到第一个 `//@` 之前为止
    - 实例（i知否 9/9）：`回复@Wootone: 目前我还是在港股混着呢…//@Wootone:回复@i知否:大人我一直跟着你在港股` → 博主原创 = 「目前我还是在港股混着呢…」，`replyTo` = 「大人我一直跟着你在港股」（原文里的 `//@Wootone:` 与 `回复@i知否:` 都剥掉，昵称不进字段）
  - **被回应者观点保留为语境（2026-09-09 固化，不单独成条目）**：回复/反驳类帖子里，被回应者的观点是博主立场的触发点/对立面，**须保留进 `replyTo` 字段**（照抄原话、不提炼不截断、不带 `//@某人：`/`回复@某人:` 包装）——**不再写成正文里的括号标注**：
    - ~~格式：`（回应"<对方核心观点，≤20 字>"）<博主观点>`~~（**2026-09-11 起废弃**：内嵌进 `view` 属违规，前端不再解析；历史数据已迁移进 `replyTo`）
    - 实例（i知否 2026-08-26，vault 已有 10 处同类写法，按新规 `view` 只留博主观点、对方原话进 `replyTo`）：`（回应"开6年纯电车已无里程焦虑"）是的，但依然很多人有；固态电池不仅改善里程焦虑，而且安全性大幅度提高…我认为未来几年能源领域里，固态电池和核电的SMR是划时代的事件`
    - **仅在有助于理解博主立场/对立面时留**（纯寒暄、无实质对立的回复可不留 `replyTo`）
  - **`//@` 后署名 = 当前博主**（自引，实测占少数）：是博主自己的旧话，**可提炼**，注意与历史批次去重。
  - **区分「原文省略」与「采集截断」**：`...//@` 中的 `...` 是雪球转发时的原文省略标记（非内容缺失，不必复核）；正文末尾单独出现 `...`/`…` 且**无 `//@`** 时，才可能是采集截断——须打开 `[原文]` 链接复核后再提炼，避免把截断句当完整观点。
  - **极简回复**（「对」「同意」「是的」等）：`//@` 前虽是博主原创但信息量为零，按「判信息量」丢或归入「互动」子表；若语境本身有信息，用上条括号标注 + 博主极简回应一起存入「互动」。
- **调侃/反讽藏观点**（博主常见）：看信息密度——反讽背后观点可提炼则留，纯乐子丢。
- **准确率未验证观点**：不算糟粕，照录进言论追踪并标「未验证」。

## 3. 言论追踪落位（2026-09-10 更新：六分法为唯一分类）

> **旧「4 类落位」已退役（2026-09-10）**：`具象化 / 观点 / 信号 / 互动` 不再作为分类维度——**分类权威 = `content_type` 六分法**（research/predict/view/insight/chat/trade，入参名 `contentType`），落库时服务端按类型路由到六张言论物理分表 `statement_research`/`statement_predict`/`statement_view`/`statement_insight`/`statement_chat`/`statement_trade`（**不是旧的 `post_*` 前缀**——2026-09-12 分层改名后：采集层叫帖子、`post_` 只属于 `post_history`）。旧 `kind` 字段仅保留历史值，**新数据不得再传 kind**。
>
> 旧四类语义已被覆盖：具象化 → `wikiRef` 字段（research/insight）+ wiki 条目；观点 → `view`；信号 → `trade`（结构化 `op`/`price`）或 `view` 的 signal 文本；互动 → 回复类帖的 `//@` 语境标注（见 §2）。

**六分法落位表（权威）**：见 `investment-refine/references/refine-schema.md`「六、博主言论分流决策矩阵」。

**优先级（2026-09-10 更新）**：P1 必录 = `trade` / `research` / **`predict`**（原 P2 提升）→ P2 = `view` / `insight` → P3 = `chat`（高门槛）。

> 各类型统一列含「原文链接」：填帖子 URL（`[原文](https://xueqiu.com/{xq_id}/{post_id})`，取自本帖 `[原文]` 链接），**禁止留空 `-`**（无来源帖链接则该行不建，见 framework-rules #35）。预测 / 个股买卖表同样须带原文链接列并填真实 URL。

## 4. 丢弃确认清单（满足任一即丢）

- [ ] 模糊个人情绪、无通用迁移价值的碎碎念
