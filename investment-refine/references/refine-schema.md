## 二、字段规范（必须遵守）

| 字段 | 必填 | 类型 | 说明 |
|:---|:---|:---|:---|
| `from` | ✅ | string | **来源标识**。常规路径＝源材料相对路径（`工作区/原始资源/xxx.md`，真实存在的文件）；**帖子集路径（2026-09-12 起）＝数据库引用 `post_history/{博主} {采集日}`**（如 `post_history/庶人哑士 2026年09月09日`）——帖子集已不落 vault，写批次文件路径会成死链（看板还会生成失效的 Obsidian 打开链接）；不带 `.md` 即按纯文本渲染 |
| `sourceType` | 建议 | string | `raw`=原始资源 / `coarse`=粗制品直提（帖子集 #29 / 直投 #30）；缺省按 from 含「粗制品」推断 |
| `source` | 建议 | string | 原文链接（markdown 格式 `[标题（博主 日期）](url)`） |
| `targets` | ✅ | array | **产物列表**，每项见下 |
| `reason` | 建议 | string | 整体拆分决策说明（为何拆成这些条目） |
| `steps` | 建议 | array | 提炼步骤时间轴（读取→分析→创建→档案→校验） |
| `bloggerUpdated` | 建议 | bool | 是否更新了博主档案（言论追踪） |
| `bloggerName` | 建议 | string | 涉及博主名 |
| `verify` | 建议 | object | 产出校验结果 `{ok, detail}`（verify-format.py） |
| `verificationHints` | 建议 | array | 可验证判断提示（建分析档案建议） |

### `targets[]` 每项

| 字段 | 必填 | 说明 |
|:---|:---|:---|
| `path` | ✅ | 产物相对路径 |
| `type` | ✅ | 英文码：`wiki`=框架条目 / `blogger`=博主言论（DB 落库，画像 md 已退役） / `macro`=宏观 |
| `layer` | 建议 | **英文码**（见下方字典表）：`my`/`blogger`/`other`/`macro`/`workspace` |
| `category` | 建议 | **英文码**（见下方字典表）：`analysis_framework`/`trading_system`/`investment_mentality`/`investment_insight`/`stock`/`industry`/`macro` |
| `tags` | 建议 | 标签（来自标签体系，一级前缀） |
| `basis` | ✅ | **依据**：原文支撑该条目的关键句引用——回答"从哪句话提炼的" |
| `thinking` | ✅ | **思考链路 v2**（2026-08-31）：自由长度对象数组 `[{kind,text,quote?,alt?}]`，按真实推理过程记录（观察/疑问/假设/查证/对比/权衡/排除/决策/结论…）；`quote`=触发该步的原文引用、`alt`=备选方案/否决理由；三个决策点（归属层/拆分/关系）必含。**禁止固定 5 步模板套话**（旧格式字符串数组仍兼容展示） |
| `relation` | 建议 | **英文码**：`new`/`append`/`complement`/`conflict_check`/`other`——判断范围按分层检索链（同作者同类分类 → 全库关键词兜底 → 新建，关键词取产物名拆分+原文实体+标签 3-5 词，检索文件名/标题/标签；见 SKILL.md 第二步第 3 条；与 C7 联动） |

## 二B、字典码对照表（避坑 · 2026-08-31 实测）

**`layer`/`category`/`relation`/`type`/`sourceType` 必须传数据库字典英文码，传中文会落库失败（外键约束报错）**。全量对照（源：远端 MySQL `investment-dashboard` 的 `dict` 单表，`type` 列区分字典域；2026-08-31 schema 整合后由多张 dict_* 合并为单表）：

| 字段 | 字典表 | 合法码（码 → 中文含义） |
|:---|:---|:---|
| `layer` | dict(type=layer) | `my`=我的 / `blogger`=博主 / `other`=其他 / `macro`=宏观 / `workspace`=工作区 / `attachment`=附件 |
| `category` | dict(type=category) | `analysis_framework`=分析框架 / `trading_system`=交易体系 / `investment_mentality`=投资心态 / `investment_insight`=投资心得 / `stock`=个股 / `industry`=行业 / `macro`=宏观 |
| `relation` | dict(type=target_relation) | `new`=新建 / `append`=追加 / `complement`=互补 / `conflict_check`=矛盾预检 / `other`=其他 |
| `type` | dict(type=target_type) | `wiki`=框架条目 / `blogger`=博主言论（DB） / `macro`=宏观条目 |
| `sourceType` | dict(type=source_type) | `raw`=原始资源 / `coarse`=粗制品 |
| 审查 `checks[].status` | dict(type=check_status) | `pass`=通过 / `warn`=警告 / `fail`=失败（`ok`=旧数据遗留，新写入不用；**无 `info`**） |

> **避坑**：落库报 `foreign key constraint fails ... dict_*` 时，用 `SHOW CREATE TABLE {refine_target_sub|review_check_sub}`（`_sub` 子表） + 对应字典表核对码值，不要猜中文。博主言论目标 `category` 可省略（列可空）。

## 四、决策一致性（质量保障）

- **自由文本路径书写硬约束（2026-09-01 用户确认，前置约束优于回检兜底）**：`reason` / `thinking`(text/quote/alt) / `basis` / `verify.detail` 等自由文本中，`xxx/yyy.md` 完整路径**只允许**指向「写入时已确认存在于 vault 的文件（本次检索命中）」或「本条 `targets[].path` 产物 / `from` 源」；假想、被否决、未创建的条目一律写《名称》（**不带 `.md`、不带路径**）。看板按此语义渲染：`.md` 路径 = 可点击跳 Obsidian，《名称》 = 纯文本。前端存在性校验只是兜底质检，写入方不得依赖它补救
- `basis`（依据原文句）必须**真实来自原文**，禁止事后编撰
- `thinking` 的「决策」步（归属层/拆分/标签判断）必须来自第一步分析的真实判断：归属层铁律（博主控制台登记）、标签体系、同作者一致性预检
- `relation`（关系）与审查 C7 关联备注提案、C3 矛盾预检联动——提炼时标注的互补/矛盾，审查时据此核对
- 落库失败（看板未启动等）不阻断提炼主流程，但汇报中必须提示「看板数据未写入，需补录」

## 七、落库前置检查八问（SKILL.md 第三步 3.0 引用）

> 由 SKILL.md 第三步「3.0 写入前双预检」引用：写入前必过，答错会被服务端拒写，返工成本高。

> **写入前必过**（不要等到自检环节）：每条言论在调用 `blogger_statement` 前，先答完八问（含九项必有字段）。答错会被**服务端拒写**（`_validateSignal` / `form` / 空壳 / sourceUrl 硬门禁），返工成本高。

| # | 落库前置问 | 不合格处理 |
|:--|:---|:---|
| **①** | **这条有方向立场吗？** | 无 → `stance` 与 `signal` **都留空**（研究结论/事实数据/观察笔记属 `view_text` 正文，**不得写入 signal**） |

| **③** | **信号够短吗？** | 超 25 字 → 精简为具体结论（方向由 stance 承载），用 `/` 分隔并列要素；**开头不得再写「看多/看空/中性」** |
| **④** | **正文干净吗？**（2026-09-11 用户确认） | 正文**只写内容本身**：出现 `见 [[…]]`、`（已提炼见 [[…]]）`、`已具象化`、`（信号：复盘）` 等**流程性标记**一律删掉——那不是博主言论，也不是提炼出的含义。已沉淀成框架条目的，条目名写 **`wikiRef`**，卡片自动显示「已具象化：[[条目名]]」 |

> **工具面两个已知限制（2026-09-30 审查固化）**：① `blogger_trade` 落库不带 `form`（工具无此入参），trade 行的 form 需从 `post_history.post_form` 回填（存量 6 条已于 2026-09-30 审查补齐）；落 trade 后核对一眼 form，空则按留档回填。② `blogger_statement` 的 update **无法清空** `wikiRef`（传空串被服务端忽略）；且服务端按 source_url 反查自动回填，在**同 URL 拆条**场景会把指针误回填到不含该内容的兄弟行上（实测 #3516 科技股行被回填贵金属条目）——拆条后逐行核对 wikiRef，误回填走 SQL 清空。

> **批量数据修复脚本纪律（2026-09-11 教训）**：修正已有言论行（如补 `replyTo`）的脚本**只改目标字段**，不得顺带覆写 `view_text`；从采集文件切段落时终点要从**本贴标题**往后找 `\n> 发布：`（从 URL 往后找会抓到下一篇）；先 dry-run 并打印「旧值→新值」，落库后复检污染指纹（`## `、`发布：`、`回复@`）为 0。完整规则见 framework-rules #43（数据库重构与「帖子只落类型表」见 #44）。

> **批量外部判断的格式风险（2026-09-11 教训）**：把提炼外包给子任务时，务必在任务书里写明「signal 不带方向词前缀」「form 必填」「正文不写 wikilink」「回应写 replyTo 字段、不内嵌正文」「**replyTo 只写对方原话、不带 `//@某人：`/`回复@某人:` 包装**」——否则会成批产出「信号：看多 · 看多…」「回应内容是雪球语法串」这类需要事后返工的数据。


**合法信号形态**（三个范例）：
```
看多 · 白酒跑赢科技 / 未来半年到一年
中性 · 中报：利润同比降但好于预期
看空 · 情怀流量无效（转化1.49%）
```

**服务端门禁**（写不进去的 8 类：另加「缺帖子时间」「回复类缺 replyTo」「预测缺 stance」「dict 外的 form」）：无方向却有 signal / signal 自带方向词前缀 / 占位符 `—` / 元描述 / 话题标签 / 超 25 字；另加 `form` 必填、正文与信号不能同时为空、`sourceUrl` 必填。


## 八、框架条目写入硬约束（自 SKILL.md 第二步下沉 · 2026-09-12）

> 权威源仍是 `framework-rules.md` 对应编号；此节为执行摘要，冲突以 framework-rules 为准。

**写入硬约束（创建/修改任何文件前必须满足，违反即重写）**：完整规则以 `framework-rules.md` 对应编号为权威源，此处为执行摘要——若与 framework-rules 冲突，以 framework-rules 为准：

- **wikilink 完整路径**（#3）：所有 wikilink（正文、source 字段、博主档案言论追踪的具象化指针）写完整路径 `[[博主/名/分类/文件名]]`，**禁止仅写 basename**。唯一例外：博主档案内指向自身文件夹下条目时可省略 `博主/{名}/` 前缀
- **个股文件名带代码**（#28）：`{名称}({代码})`，代码缺失时联网检索确认，不得留空
- **禁止 `## 来源` 段落**（#23）：来源一律写入 frontmatter `source` 数组，正文不设该 section
- **`source` 填真实原文链接**（#23/#29）：`source` 数组填原文链接（markdown 格式 `[标题（博主 日期）](https://xueqiu.com/.../XXXXXX)`，取自批次 `[原文]` 链接），**禁止填采集批次文件名**（批次提炼后即删，会成悬空引用）；综合多篇帖则列多个链接
- **模板 section 全量输出**：按所属分类模板的 section 结构全量输出（标题 + 内容）。某 section 确实无内容时写一句最小说明（如"暂无验证记录"），**不得省略 section 标题**
- **frontmatter 字段顺序 canonical**（#27）：按模板定义的字段顺序写入，禁止打乱
- **`star` 缺省 false**（#27）：内容型条目（方法论/分析档案/交易体系/心态/心得/行业/宏观/个股）frontmatter 一律含 `star: false`（位于 author 后），**提炼阶段不推断不打星**，由用户手动改为 true

- **产出物去 emoji**（2026-08-09 用户确认边界）：wiki 产物与落库文本（框架条目、`view_text`/`signal_text`/`strengths`/`limitations` 等 DB 字段）**禁止任何 emoji 表情**——标题、正文、frontmatter 均不得含 emoji 表情字符；`→` 流程箭头、表格 `---` 分隔线等非表情符号不受限。**该边界只影响提炼环节**：采集（xueqiu-spyder）与粗加工（coarse-processor）必须保持原文（含原文 emoji），不得清洗

**`predict` 判定（2026-09-14 放宽，用户明确拍板）**：判据只有两条——① **未来指向**（时间窗："几年后/几个月后/年内"，或事件条件："美国加息/降息""地缘冲突缓和"等）② **方向**（`stance` 必填）。**「可判对错 / 可验证」不再是门槛**：只要是对未来的判断就归 `predict`；有目标位/幅度/点位就写进信号列（能验证的才进预测控制台闭环），没有也不影响归类。缺**未来指向**才回落 `view`（当下判断）或 `insight`（复盘心得）；历史复盘叙述**不得**算预测。

**易错例（仍成立）**：`白酒处于底部（公募持仓全面退出为信号）` → `view` + `stance=bullish`——它讲的是**当下状态**、整段没有未来指向，所以不是预测（**不是因为"没有可验证目标位"**）。
**正例（2026-09-14 用户判例，老雷_ 400717196）**：「上一轮牛市大幅上涨的个股在这轮表现都很差……在这轮牛市大幅上涨的个股在下一轮牛市表现会很差，这些个股至少 5 年内没有机会」→ `predict`（有未来指向 + 方向）。**没有点名具体标的、没有目标价、不可精确验证，都不影响归类**；标的按「没点名个股但有市场线索 → 挂市场」处理（见 `stock-mention-rules.md` 第四节）。

**信号（`stance`）规范（2026-09-11 用户确认扩展）**：**所有 `content_type` 均可携带信号**（研究/心得/观点/闲聊都可表达方向），**无信号则不填**（页面不显示该行）。

**信号取值（6 种方向 + 中性）**：

| 码值 | 含义 | 适用 |
|:---|:---|:---|
| `bullish` | 看多 | 不限时间的方向 |
| `bearish` | 看空 | 不限时间的方向 |
| `short_bullish` | 短期看多 | 明确短期（数日~数周） |
| `short_bearish` | 短期看空 | 明确短期 |
| `long_bullish` | 长期看多 | 明确长期（数季~数年） |
| `long_bearish` | 长期看空 | 明确长期 |
| `neutral` | 中性 | **正式取值**：明确表达「不好不坏/多空交织/结果未定」的判断（**不是「无信号」**） |

> 时间维度**只在原文明确时**用 short/long 变体；泛泛看好用 `bullish`，不得臆测时间跨度。

**信号依附于方向（2026-09-11 用户确认，硬约束）**：`signal_text` 是 `stance` 的**内容补充**，**必须依附方向存在**：

| 情形 | `stance` | `signal_text` | 页面 |
|:---|:---|:---|:---|
| 有方向判断 | 填（6 种+中性） | 填具体内容 | `信号：方向 · 内容` |
| **无方向**（研究结论/事实记录/观察笔记） | **留空** | **必须留空** | **不渲染** |

- **研究要点、事实数据、观察记录属于 `view_text`（正文），不得写入 `signal_text`**
- 反例：`research` 类「大模型转全栈竞争 / Gemini降价腰斩」——这是**研究结论**（无方向），不是信号 → 该条 `stance`/`signal_text` 均应留空
- 判据：**这条记录有方向立场吗？没有 → 两个字段都不填**

**信号书写规范（2026-09-11 用户确认，硬约束）**：信号由两个字段合成，页面显示为 **`信号：{方向} · {具体判断}`**：

| 字段 | 内容 | 例 |
|:---|:---|:---|
| `stance` | 方向码值（6 种 + 中性） | `bullish` → 显示「看多」 |
| `signal_text` | **简短的具体判断**（目标 ≤20 字 / 上限 25 字） | `白酒跑赢科技 / 未来半年到一年` |

| 规则 | 说明 |
|:---|:---|
| **简短明了** | 一句话说清，**目标 ≤20 字、硬上限 25 字**；用 ` / ` 分隔并列要素（标的、判断、时间窗）。达标以「信息密度」为准：宁可 21-25 字的完整结论，不要 15 字的空泛表述 |
| **不得只有方向** | 信号内容必须给出**具体指向**（标的/判断/时间窗），**不能只写"看多/看空"**——除非原文确实只能判断出方向（如"我看好，但说不出具体"） |
| **不得自带方向词前缀（2026-09-11 用户报错新增）** | `signal_text` **开头不得再出现「看多/看空/看涨/看跌/短期看多/短期看空/长期看多/长期看空/中性」**：方向由 `stance` 承载，页面渲染为 `信号：{方向} · {内容}`，再写方向会出现 `信号：看多 · 看多 …` 的重复。<br>❌ `stance=bullish` + `signal_text="看多 · 医药刚回本，高位加仓难"` → 渲染「看多 · 看多 · 医药刚回本…」<br>✅ `stance=bullish` + `signal_text="医药刚回本，高位加仓难"`<br>❌ `signal_text="看多铀 · 稀缺性支撑"` ✅ `signal_text="铀 · 稀缺性支撑"`（标的名可保留，方向词必须去掉）<br>**服务端已加硬门禁**（`_validateSignal` 第 ⑤ 条，写入即拒），前端 `stripDirPrefix` 兜底剥离历史数据 |
| **一帖多信号（2026-09-11 用户确认）** | 一条帖子常含多个信号，判定时**必须逐个识别，不得只提炼一个**：<br>· **同向多结论** → 仍落一条，`signal_text` 用 ` / ` 分隔（如 `创新药跌了回补 / 医药刚回本`）<br>· **异向（一多一空）或多标的** → 按下方判据 ⑥「多对象必拆」**拆成多条**（每条一个 target + 一个 stance）<br>· **实例**：metalslime「减仓也没卖到最高；创新药这些是跌了我会回补的方向，AI4S 啥的我肯定不会回补，卖了就卖了」= 两个异向信号 → 拆两条：`trade · AI4S · 看空 · 已卖出不再回补` + `view · 创新药 · 看多 · 跌了会回补` |
| **时间窗写进内容** | 有明确时间跨度时写在这里（如 `/ 未来半年到一年`），不要臆造 |
| **中性也是信号** | `neutral` 与「留空」是两件事：<br>· `neutral` = 博主**明确表达了中性判断**（多空交织/结果未定）→ 填 `stance=neutral` + 具体内容<br>· **留空** = 博主**未表达方向** → 信号行不渲染 |
| **示例（用户认可的写法）** | `信号：看多 · 白酒跑赢科技 / 未来半年到一年`<br>`信号：看多 · 铀：稀缺性支撑，估值偏高`<br>`信号：中性 · 中报：利润同比降但好于预期`<br>`信号：短期看空 · 创业板破位后反弹结束` |

> **判据**：删掉方向后，剩下的内容还能不能让人知道"博主在说什么"？不能 → 信号内容不合格，须补具体指向。

**禁止笼统标签（2026-09-11 用户确认，硬约束）**：信号内容**不得只写话题名/动作名**——那只是「在说什么话题」，不是「判断是什么」。必须写出**具体事实或结论**：

| 反例（不合格） | 问题 | 改写（合格） |
|:---|:---|:---|
| `中性 · 中报点评` | 看不出中报怎么样 | `中性 · 中报：利润同比降但好于预期` |
| `看多 · 业绩分析` | 看不出结论 | `看多 · 净利同比+30% 超预期` |
| `看空 · 行业跟踪` | 看不出依据 | `看空 · 排产环比下滑` |
| `看多 · 复盘` | 零信息 | `看多 · 上一轮同形态后涨 3 倍` |
| `看多 · 基本面判断` | **元描述**——只说了「我做了个判断」 | `看多 · 毛利率环比改善` |
| `看多 · 投资信念` | **概念名**——信念内容是什么？ | `看多 · 相信管理层执行力` |

- **禁止词**（单独出现即不合格）：点评 / 分析 / 跟踪 / 复盘 / 梳理 / 解读 / 汇总 / 思考 / 记录 / 更新 / 分享
- **禁止元描述/类别名（2026-09-11 补充）**：『X 判断』/『X 观点』/『X 信念』/『X 逻辑』/『X 框架』/『X 体系』这类**只描述「哪一类」而不说「是什么」**的表述一律不合格。常见不合格组合：基本面判断、估值判断、投资信念、行业观点、成长逻辑、周期框架。**必须替换为该判断的具体内容**（事实、数据、结论、理由）
- **判据（一句话）**：信号必须回答『**是什么**』（具体事实/结论），而不是『**哪一类**』（话题名/概念名）。单独读信号内容若只能知道「他在谈哪个话题」、不知道「他的结论是什么」→ 不合格
- 注意与「不得只有方向」的区别：那是**缺内容**，这是**内容空泛**——两者都要补具体指向

**证券信息必须查证，判不了不许落地（用户指令 2026-09-28，中免判例）**：提炼遇到**需要查询证券信息**的场景——市场归属/角标、股票代码、上市板、A+H/多地上市归属、称呼归属歧义——**一律先查证再落库，禁止凭记忆猜、禁止直接落地**：

- **市场归属判定（A+H/多地上市且原文未写明）**：拿**言论中的价格线索**对两个市场的历史价判定——原帖时点哪个市场的价位与所述价格量级吻合（判例：鹅总投资笔记「中免60以下随便买」(2024-08)——A股 61~64 元正贴 60 关口、构成条件，港股 48~54 港元恒低于 60、不构成条件 → 判 A股 601888）。

- **体系外标的**（新三板/港股美股之外的市场）**不落个股实体，言论改挂行业**（2026-09-28 盘点判例：马士基→航运、粤开证券→证券、奥维云网(831101 新三板)→IT服务；行业用 `industry_sw_list` 查申万标准名后 `console_ensure_subject` 建档）。

### 分类不明处置（禁止静默丢弃 · 2026-09-06 用户规则）

分流时遇到 **①不属于任何既有 content_type**、或 **②定位模糊**（多类型皆可 / 明显有价值但去向不明）的言论：

1. **禁止丢弃、禁止强行套类**——强行套类会污染准确率追踪与子表结构，静默丢弃会永久丢失高价值言论，两者都比「列出来问一句」代价高。
2. **必须在执行汇报中单列「⚠ 待确认分类」一节**，逐条给出：原文全文（不得截断改写）、不确定原因（如「既有研究成分又有交易动作」「既非当下判断也无未来指向但明显是方法论雏形」）、候选建议（最接近的 1-2 个既有类型 + 理由，或「建议新增分类」+ 建议类名中英文名，供 dict 录入）。
3. **用户裁决两种结局**：**指定归属** → 按指定 content_type 正常经 `blogger_statement` 落库；**新增分类** → 走 dict 字典流程（`INSERT INTO dict`，type=`post_content_type`，remark 存判据、sort_order 定序，framework-rules #30 码值权威源——**只改字典，服务端校验与前端标签/tab 自动生效**，禁止在代码里加并行定义），再落库。
4. **裁决前**：该言论不写入任何表、也**不丢弃**，保持在待确认清单中（宁挂起、不流失）。
5. 「能成 wiki 的一刀切判据」仍然适用：分类不明 ≠ 没价值；确定有价值只是去向不明的，必须走本流程而不是丢弃。
