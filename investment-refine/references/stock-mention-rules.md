# 个股提及与别名判定规则（关键词邻接 + 二元分类特征）

> 用途：提炼一条言论时，判断文中出现的词**是不是个股**、**指的是哪只股**，从而决定是否写 `statement_stock_rel`。
> 起因（2026-09-12 用户提出）：博主常写代称（寒武纪→「寒王」、中芯国际→「中芯h」、科大讯飞→「讯狗」、中远海控→「海控」），
> 而有些词**既是常用词又是股票简称**（美的、长江、中免、平安），机械匹配会把「美的房子」「长江后浪」误判成个股。
> 本文件给出**可执行的判定流程**：先看硬信号，再看邻接窗口，最后用二元特征打分，分数不足就不建关联。

## 一、三档判定流程（命中即止，逐档降级）

> **粒度（2026-09-12 硬规则）**：一律**按标点分句**独立判定，同帖多次出现各自算分——**禁止因为同帖某句命中就把整帖其它出现的同一个词也判正**。
> 反例（标准答案）：帖子「好美的风景，买点薯片来吃」「美的业绩不行，空调卖不出去」
> —— 第 1 句判**非个股**（形容词用法，N1）；第 2 句判**个股·美的集团**（F7：同句「空调」命中美的集团主营；邻接「业绩/卖不出去」属经营与产品类）。

### 第 1 档：硬信号（命中判「个股」，**但歧义词例外**，见下）

> **歧义词规则（2026-09-12 用户要求）**：别名命中后若该词在 **`dict(type='ambiguous_word')`**（本身也是常用词：美的/小米/平安/长江/中免…）
> → **不直接判正**，必须再过第 2 档邻接与 F7 产品词共现；只有专有代称（寒王/讯狗/海控）命中才免上下文直接判正。
| 硬信号 | 例 |
|---|---|
| 雪球标签写法 `$…$` | `$贵州茅台(SH600519)$`、`$中远海控(601919)$` |
| 名称/代号后紧跟括号代码 | `腾讯控股(00700)`、`寒武纪(688256)` |
| 库内命中：`stock.name` 精确等于该词 | 名字本身已是登记的个股名 |
| 库内命中：`stock.aliases` 含该词（逗号分隔） | 别名库里的「寒王」「讯狗」 |
| 库内命中：`stock_name_history` 含该词（**曾用名**，2026-09-21 新增） | 历史帖里的旧简称「G茅台」「西安民生」「深发展A」——服务端解析优先级 现名>别名>曾用名，命中即硬信号，**不必上报待决策** |

**代码 → 市场（2026-09-13 用户口径；`stock.market_code` 与「个股」tab 的市场筛选都按这套判）**：
雪球帖里标的名一般写成「名称(代码)」，**代码本身就带市场信息**——

| 市场 | 代码形态 | 例 |
|:--|:--|:--|
| **A 股** | `SH`（60/688 开头）／`SZ`（00/30 开头）／`BJ`（83/87/920 开头），**六位数字**；帖子里括号内常带交易所前缀 | `泸州老窖(SZ000568)`、`寒武纪(688256)`、`北交所 830799` |
| **港股** | **五位数字** | `腾讯控股(00700)`、`小米集团(01810)` |
| **美股** | 英文代码 | `INTC`、`SPCX`、`LAZR` |
| **不是股票** | `ZH` 开头＝**雪球组合**（`$名称(ZH123456)$`） | 只留 `target` 文本，**不得建个股** |

> 库里 `stock.code` 存的是**不带交易所前缀**的六位/五位/英文码，所以判市场看**首位**：`60/68/00/30/83/87/920` → A 股、五位数字 → 港股、英文 → 美股。
> **两个坑**：① **六位数字会撞车**——韩股 `000660`（SK海力士）恰好是「00 开头」，按形状会推成 A 股，所以**回填时一律不覆盖已有的 `market_code`**，新建时也应由调用方显式传 `market`；② `—`/空代码推不出来（如马士基），**留空是正常的**，它只在「个股（全部）」里出现（framework-rules #52：无关联/无市场不是缺陷）。
> 服务端已有 `deriveMarketFromCode()` 兜底（新建个股没传 `market` 时从代码推），回填脚本 `~/Project/investment-dashboard/scripts/backfill-market-code.js`。

> 组合代号 `$名称(ZH123456)$` **不是个股**（雪球组合），按 `<框架>/framework-rules` 处理：只留 `target` 文本。
> 指数/ETF/基金（`$恒生指数$`、`$沪深300$`、`$中概互联ETF$`）也不是个股；**ETF/LOF 更不得建档为个股**（2026-09-29 用户拍板，服务端门禁：名称含 ETF/LOF 拒建 stock 主题）——ETF 落**对应申万行业**（通信ETF→通信设备），命中 `index_catalog` 的才建指数主题。

### 第 2 档：关键词邻接（**先分句，再分级**；2026-09-12 v2.1 修正）

> **先按标点（，。；！？\n）切小句，只在「该别名所在的小句」内找证据**——跨小句不算。
> 反例（血的教训）：`好美的风景，买点薯片来吃` 若按 8 字窗口，`买点薯片` 的「买」会落进窗口，把「美的」误判成美的集团。
> 分级（同一小句内）：**紧邻（±2 字内）动作/经营词 = 强证据 2 分**；同小句出现 = 弱证据 1 分；产品词（F7）同小句 = 2 分。
| 邻接类别 | 词表 |
|---|---|
| 买卖动作 | 买/买入/加仓/减仓/清仓/卖出/割/建仓/止盈/止损/抄底/补仓/仓位 |
| 价格与估值 | 股价/价格/估值/PE/PB/市值/目标价/单价/元/港元/美元 |
| 持仓与账户 | 持仓/成本/浮盈/浮亏/套住/解套/底仓 |
| 交易语境 | 开盘/收盘/涨停/跌停/换手/成交量/回调/破位/新高 |
| 市场标签 | A股/港股/美股/科创板/创业板/主板/北交所/港股通 |

> **市场主题是封闭清单（2026-09-12 用户拍板）**：上表这类词只用于**个股提及判定**的邻接语境；
> 落 `target`（→ `statement_market_rel`）时市场只有 9 个：**A股 / 港股 / 美股 / 韩股 / 汇率 /
> 虚拟货币 / 美债 / 国债 / 日债**（`大盘`、`××股市`、`××市场` 一律不是市场；A股/沪深、加密货币、
> 人民币汇率、美国国债、日本国债 等写法服务端会自动归一到标准名，返回体的 `name` 是实际落点）。
| 同现代码 | 同句出现 `\d{5,6}`、`[A-Z]{1,5}\d{1,5}`、`ZH\d+` |
| **经营与产品**（2026-09-12 补） | 业绩/营收/净利/毛利/销量/渠道/库存/产能/主营/提价/降价/亏损/毛利下滑 + 具体产品词 |

### 第 2 档之补：「别名 + 的 + N」结构（v2.2 新增，专治修饰语误判）
| N 的性质 | 判定 | 例 |
|---|---|---|
| N 命中该股 `keywords`（产品/主营词） | **link** | 「小米的**手机**」「美的的**空调**」「小天鹅被**美的**收了」 |
| N 是食品/生活名词 | **skip** | 「小米的**馒头**」「苹果的**味道**」 |
| 其它/判断不了 | doubt | 「小米的**选择**」（可能是"小米这家公司的选择"，也可能是别的） |

### 第 3 档：二元分类特征打分（每项 1 分，**≥2 分判个股；=1 分判存疑；0 分判非个股**）

**否决集（v2.2 扩充：生活/食品语境一出即判非个股）**
| 类别 | 词表 |
|---|---|
| 生活动作 | 吃/喝/煮/熬/蒸/炖/买了来吃/下厨/早餐/晚饭 |
| 食品与食材 | 粥/馒头/米饭/面条/豆浆/糕点/口感/甜/香/糯/营养/粗粮/杂粮 |
| 消费场景 | 超市/菜市场/买菜/囤货/快递到家 |

> **「食物/日用品同名股」再加一档（v2.2）**：有些股名本身就是食物或日常物（`dict(type='food_homonym')`：小米、苹果…）。
> 这类词**只有证券语境词**（股票/股/仓位/持仓/市值/估值/PE/财报/港元/元/A股/港股/割/抄底）**或该股产品词**（手机/SU7/汽车）才能判 link；
> **仅出现买卖动作词（买了点…）不足以判正 → 判 doubt**（「今天买了点小米」既可能是买粮食也可能是买股票，交复核）。

**正向特征（是个股时容易成立）**
| # | 特征（布尔） | 判定依据 |
|---|---|---|
| F1 | 词形像公司简称 | 2–4 字，或以 股份/集团/控股/科技/医药/电力/银行/能源/重工 结尾 |
| F2 | 首次出现带全称，后续用简称 | 同一帖里先出现全称再出现该简称（简称→全称映射） |
| F3 | 与已知个股共现 | 同句/同段出现其它已登记个股名或代码 |
| F4 | 与已知行业共现 | 同句出现库内行业名（半导体/白酒/电解铝…） |
| F5 | 博主历史惯用 | 该博主历史言论里该词高频出现且都伴交易/估值语境 |
| F6 | 句子主语是博主行为 | 「我在」「我买」「我持有」「我的仓位」+ 该词 |
| **F7** | **产品/主营词匹配**（决定性，2026-09-12 补） | 该词在 `stock.keywords`（主营/产品关键词）里的词与**同句**共现，如「美的…空调」「宁德时代…电池」 |

**负向特征（不是个股时容易成立）**
| # | 特征（布尔） | 判定依据 |
|---|---|---|
| N1 | 通用词/形容词用法 | 「美的」（漂亮的）、「长江」（江河）、「平安」（平安无事）、「小狗/隔壁」（口语） |
| N2 | 行业/主题词 | 词本身在 `industry` 或行业通用词表（半导体、光模块、创新药） |
| N3 | 指数/ETF/组合 | 含 指数/ETF/基金/组合，或 `ZH` 代号 |
| N4 | 人名/机构/平台名 | 邻接「老师/大佬/雪球/东财/券商」，或本身就是博主名 |
| N5 | 时间/数量词 | 邻接「年/月/日/倍/个点/%」，且无买卖词 |
| N6 | 纯代号且不可还原 | 小写拉丁短名（`cww`）且全帖无线索（服务端门禁也会拦） |
| N7 | 泛指集合 | 邻接「们/这些/那些/一批」，如「这些个股」「大佬们」 |

**打分判定（v2.1：负向一票否决优先）**
- **先看负向**：命中 N1（`好/真/太/多/美景/风景` 这类程度副词+名词/形容词用法）→ **直接判非个股，不再累加正向**（否则「买点薯片」的「买」会把分数顶上去）
- 得分 = 正向命中数 − 负向命中数
- **≥2 → 判个股**（歧义词必须满足「紧邻动作词」或「同小句产品/经营词 ≥2」才算 ≥2）：写 `statement_stock_rel`，并确保该股有行业关联（`stock_industry_rel`，缺则按邻接的行业词补建）
- **=1 → 存疑**：不建关联，把该词原样留在 `target` 文本，并置 `is_review_required=1`，进「待确认」清单
- **≤0 → 判非个股**：不做任何关联（不要为了"看起来完整"硬塞）

## 二、别名库维护（判定的沉淀物）
1. **来源**：买卖帖的 `target_alias`（提炼时留痕的原帖代称）→ 回填 `stock.aliases`（逗号分隔）
2. **新增别名时**：只加**该股专属**的代称（寒王、讯狗、海控）；**不要把通用词加进别名**（美的、平安、长江、中免）——它们同时也是常用词，进了别名库会让「好美的风景」直接命中个股。通用词只能靠第 2/3 档上下文与 F7 判。
2b. **产品/主营词放 `stock.keywords`，不放 `aliases`**（2026-09-12 新增列）：`keywords` 存该股主营与产品关键词（如 美的集团 → `空调,暖通,家电,小天鹅,库卡`），只用于 **F7 同句共现判定**；`aliases` 存专有代称。二者分工不同，不要混。
3. **别名冲突处理**：若一个词同时像两只股的简称（如「中免」→ 中国中免 vs 中免集团），以**同帖硬信号（代码/`$…$`）**为准；无线索则按存疑处理
4. **复现检查**：每批提炼后，对存疑词复盘一次；确认的补进别名库，否证的记入下方清单

## 三、常见误判清单

> **案例进库，文档只留范例（2026-09-12 用户提出「规则会一直迭代、量会很大」）**：
> 本节只保留最具教学价值的几条；**新增案例一律写进数据库**：
> ```
> stock_alias { "action":"case-add", "sentence":"原文片段", "value":"句中称呼",
>               "stockName":"正确归属（skip 时省略）", "verdict":"link|doubt|skip",
>               "reason":"命中了哪条规则/被哪条否决", "source":"refine|review|user" }
> stock_alias { "action":"case-list", "value":"美的" }   # 查询已有案例（可做回归）
> ```
> 存放表 `mention_case`（sentence/alias/stock_id/verdict/reason/source），可被工具查询、可做回归测试。
> 这样文档不会随案例无限膨胀，而**判定算法与机制**留在这里（那是几乎不变的部分）。

（出现即按负向特征处理；完整案例库见 `mention_case`）
| 词 | 为何易误判 | 正确处理 |
|---|---|---|
| 美的 | 「美的风景/美的房子」是形容词；「美的业绩/美的空调」是美的集团 | **v2.2 标准答案（小米四句连测，2026-09-12 用户出题）**：
`今天吃了点小米` → **skip**（生活动作+食材名：吃 / 食物同名股无证券语境）；
`今天买了点小米` → **doubt**（只有动作词「买」，食物同名股不足以判正 → 交复核）；
`今天买了点小米的馒头来吃` → **skip**（「小米的馒头」= 修饰语，N 是食品名；且「吃」在否决集）；
`今天吃了点小米，然后决定卖出小米的股票` → **前小句 skip / 后小句 link**（同一词在两句里含义不同——**必须分句判定**，后半句有「卖出」+「股票」双重证券证据）。
> 教训：**动作词单独不足以判正**；对食物同名股必须有证券语境词或产品词；结构（`别名+的+N`）与否决集要一起看。

**v2.1 标准答案（三句连测）**：`好美的风景，买点薯片来吃` → skip（N1 程度副词+名词，一票否决）；`美的业绩不行，空调卖不出去` → link（同小句经营词 3 个 + 产品词 空调）；`寒王的业绩不及预期` → link（专有代称免上下文）。**注意**：v2.0 用 8 字窗口会把第 1 句的「买点薯片」算成证据而误判 link——必须分句+分级 | **两例句已定为标准答案**：`好美的风景，买点薯片来吃` → 非个股（N1）；`美的业绩不行，空调卖不出去` → 美的集团（F7 同句「空调」+ 经营类邻接）。通用词不进别名库，全靠上下文 |
| 长江 | 长江电力简称，也是江河 | 需邻接「电力/水电/长电」或硬信号 |
| 中免 | 中国中免简称，也是机构名的一部分 | 看是否带代码或 `$…$` |
| 平安 | 平安无事 / 中国平安 | 邻接「保险/银行/集团」才算 |
| 小单 / 大光 / 隔壁 | 博主行话（小单不动如山、隔壁被禁） | 不是个股；留在正文 |
| 狗狗 / 猫猫 | 口语化代称 | 除非别名库已登记，否则不建关联 |
| 这些个股 / 大佬们 | 泛指集合 | 不建关联 |
| 通信ETF / Tema光子与光学ETF | ETF 被当成个股建档；后者还抢占了 `LAZR` 代码（LAZR 实为 Luminar 公司，真身反而不在库） | ETF **不建 stock 实体**，挂对应申万行业（通信ETF→通信设备）；案例已进 `mention_case`，服务端门禁拒建（2026-09-29） |
| 通胀 / 利率 | 宏观概念，**不属于市场** | 不建 `statement_market_rel`（用户明确：通胀不属于市场） |

## 四、与落库动作的对应
| 判定结果 | 落库动作 |
|---|---|
| 个股（≥2 分或硬信号） | `statement_stock_rel` + 该股 `stock_industry_rel`（缺行业则补） |
| 存疑（=1 分） | 不建关联；`target` 保留原词；`is_review_required=1` |
| 非个股（≤0 分） | 不建关联（词留在正文本就够） |
| 博主 | **每条言论必挂** `statement_blogger_rel`（用户明确：言论可以没有个股/行业/市场，但一定有博主） |
| 行业 | 命中 `industry_sw` 标准名才建 `statement_industry_rel`，且**取最细的准确级**（能三级不二级）——用 `industry_sw_list` 查、**挂个股行业前也先查**；**泛称（AI/科技/消费/新能源）不许当行业名直接挂**，先判实际赛道再落到具体申万名（见 framework-rules #61）；申万无原生主体的（美股等）允许 0 行业 |
| 市场 | 命中 `market.name`（封闭清单 A股/港/美/韩股/汇率/虚拟货币/美债/国债/日债）才建 `statement_market_rel`；清单外（通胀/大盘/板块）不是市场（#61/#200） |

> **没点名个股但有市场线索 → 挂市场（2026-09-14 用户拍板，老雷_ 判例）**：正文（含帖子里的截图）通篇都是**某一个市场的股票**、却没有点名任何一只具体个股时——**不建个股，也不要留空**，把该市场建成主题关联（如 `A股`）；反过来，**点名了具体个股 → 建个股**（再按 `stock_industry_rel` 挂行业）。判断依据是"有没有明说具体标的"：**明说 → 个股；没明说、只有市场线索 → 市场**。市场仍是封闭清单 9 个（A股/港股/美股/韩股/汇率/虚拟货币/美债/国债/日债），清单外一律不建。
> 判例：老雷_ 2026-07-17「上一轮牛市大幅上涨的个股在这轮表现都很差……下一轮牛市表现会很差，至少 5 年内没有机会」——正文与截图里都是 A 股个股、却没点名任何一只 → `statement_market_rel` 挂 **A股**（用户原话：「截图的都是 A 股的股票，但没明说具体什么股票；有明说就可能是个股，没明说就是在暗示 A 股」）。

**库外称呼处置（2026-09-21 用户拍板三分支）**——称呼在库里全部未命中（现名/别名/曾用名，第 1–3 档都没判上）时：
| 情况 | 判定 | 动作 |
|---|---|---|
| ① 疑似改名，**文中有代码** | 拿代码查库（`stock.code`，A/HK/US 代码形态都认） | 命中库内股＝**个股改名**：挂该股，旧称呼经 `stock_former_name(add)` 沉淀为曾用名；服务端行情标签解析同口径（名称不在库→代码查库复用，不建重复实体） |
| ② 疑似改名，**无代码** | 不猜 | **先当新个股处理**（走 ③），不得凭名字相似硬挂 |
| ③ 库外新个股 | 确认是股票（非指数/ETF/组合） | 建档三步：`console_ensure_subject`（名+代码+市场）→ 曾用名（跑 `scripts/fetch-stock-former-names.js`，港/韩人工）→ 再落库关联 |
| ③b ETF/LOF 基金（通信ETF、中概互联ETF…） | **不是个股** | **不建个股实体**：挂对应申万行业（用 `industry_sw_list` 查最贴的标准名，通信ETF→通信设备）；命中 `index_catalog_list` 的才建指数主题。服务端门禁会拒绝 ETF 建档并返回此指引（2026-09-29） |
| ④ 觉得是个股但拿不准（可能是别名/可能非个股） | 存疑 | **交用户决策**：`pending_decision(add)` 带 excerpt 原文片段 + options 候选（不得瞎猜、不得硬挂）；用户拍板后按既有闭环内化（别名→stock_alias add / 曾用名→stock_former_name add） |

## 五、维护节奏
- 每批提炼后跑一次「存疑词清单」复盘 → 确认的补 `stock.aliases`，否证的补进第三节清单
- 别名库与行业关联由**服务端写入**（`blogger_statement` 落库时同步），不要手改数据库

## 六、别名与规则的迭代机制（学到的必须落库；2026-09-12 用户要求）

> 用户原话：「提炼或者审查发现我的复核有什么，修正后比如美的指的是美的集团，你要记得把它更新到 stock 的 aliases，并且更新对应的规则……
> 后续如果知道或者我复核后你知道了，你要记得迭代规则。」→ 因此**知识不能只留在对话里**，必须落库 + 改规则。

| 触发时机 | 谁执行 | 必须落库 / 更新 |
|---|---|---|
| 提炼时遇到未登记的称呼（如 寒王=寒武纪、讯狗=科大讯飞、小米=小米集团） | 提炼环节 | 调 `stock_alias(action=add, stockName, value)` 写入 `stock.aliases`；顺手 `set-keywords` 补该股主营/产品词 |
| 新增个股建档 / 获悉公司改名 / 曾用名缺口（2026-09-21 新增） | 提炼环节或人工 | 跑 `node scripts/fetch-stock-former-names.js`（幂等可重跑：A股东财 + 美股 EDGAR 自动导入；**港股/韩股暂无免费结构化源**，只能 `stock_former_name(action=add)` 人工补）。公司真改名：改 `stock.name` 正名 + **旧名必须同时 add 进曾用名表** + 清缓存 + `POST /api/stats/rebuild`（正名一处改，页面全跟；统计表冗余主体名需重算矫正）——曾用名与别名分工见 §七 |
| 提炼时判断该称呼**同时也是常用词**（美的/小米/平安/长江/中免） | 提炼环节 | 调 `stock_alias(action=mark-ambiguous, value=该词)` → 落 `dict(type='ambiguous_word')`，此后该词命中必须过上下文 |
| 审查发现误判（如「好美的风景」被挂成美的集团） | 审查环节 | ① 修正言论关联（`blogger_statement(action=update)` 改 target/或删除错误 rel）② 查因：缺歧义标记就 `mark-ambiguous` ③ 把案例写进本文第三节误判清单 |
| 用户复核（看板左滑「这条应是…」）确认了某个称呼的归属 | 复核处理流程（`console_statement_review`） | 落实修正后**必须**回填别名（同上第一/二行），并把结论写进本文档；不允许只改那一条言论就结束 |
| 发现规则本身判错（新语境、新反例） | 提炼/审查/用户任一方 | **直接改本文件**（误判清单 + 特征表），并同步到四个 skill 根 |

**三条铁律**
1. **别名 ≠ 通用词**：`aliases` 可以收录常用词（美的/小米），但**必须同时登记为歧义词**，否则「好美的风景」当场误判；两件事永远一起做。
2. **落库优先于记忆**：任何口头/对话里确认的映射，当场调 `stock_alias` 落库；只在对话里说过 = 下一步就会忘。
3. **规则是活文档**：每修一个误判，本文件第三节清单要加一条（词 + 为何易误判 + 正确处理），规则随数据一起长。

## 七、存储与容量（2026-09-12 用户提问后定案）

| 内容 | 存在哪 | 为什么 |
|---|---|---|
| 别名（称呼：寒王/讯狗/美的/小米） | `stock.aliases`（**每股一行**，逗号分隔） | 天然按股分片；500 股 × 5 个别名也才 2500 条，工具一条查询全取回；与个股生命周期绑定 |
| 主营业务/产品词（空调/思元/SU7） | `stock.keywords` | 同上，且 F7 判定只按句内共现取用 |
| 曾用名（官方历史简称：G茅台/西安民生/深发展A/Pinduoduo Inc.） | `stock_name_history` 表（2026-09-21 新增） | **官方改过名 ≠ 俗称**，不进 `aliases`；导入用 `scripts/fetch-stock-former-names.js`（A股东财 + 美股 EDGAR 自动；**港/韩无免费结构化源，人工 `stock_former_name(add)` 补**） |
| 歧义词（本身是常用词） | `dict(type='ambiguous_word')` | 「与常用词同形」是**词的属性**，不是某只股的属性；登记一次全局生效 |
| **判定案例（会一直长）** | **`mention_case` 表** | 每修一个误判就多一条；进库后可用 `stock_alias(case-list)` 查询、可做回归测试；避免文档无限膨胀 |
| **判定算法**（分句/分级/否决/阈值） | **本文件** | 几乎不变的「程序」，给人读也给 agent 读 |
| 机制（何时该落库、谁来做） | 本文件 §六 | 同上 |

**为什么不用单独一个 JSON 文件**：那会成为**第二个真相源**——库里一份别名、文件里一份，两边迟早不一致（用户反复强调过「一个东西不许存两处」）。MySQL 本身就是结构化存储，工具与看板都能读，JSON 文件在并发写、备份、查询三方面都更差。

**容量判断**：别名与产品词的增长是**行内**增长（每股一行、几十字符），不会让任何一张表变大；真正会无限增长的是「案例」和「误判教训」，所以那两类**一律进 `mention_case`**，md 只留算法 + 机制 + 少量范例（当前 5 条）。
