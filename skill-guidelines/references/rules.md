# 工程细则

> 只放 `SKILL.md` 与 `principles.md` 未承载的操作细节。阶梯、单一来源、执行优于模拟、指针写法这些不在这里重述。

## 默认行为要逐个写清

一份 skill 对未指定输入的态度，就是 agent 那一步的自由发挥空间。逐项给答案：

| 未定项 | 要有定义 |
|:---|:---|
| 输入为空 | 报错停止，还是按默认值继续？ |
| 路径未指定 | 取当前目录，还是问用户？ |
| 格式未指定 | 选一个默认格式并写明 |
| 来源冲突 | 谁赢（见 `SKILL.md` Source hierarchy） |

## 测试用例分三类

`testing.md` 跑的是真实提示词验证；这里定义**用例本身**该覆盖什么：

1. 正常输入 → 期望输出
2. 缺失字段 → 期望报错（不是静默继续）
3. 边界输入 → 期望行为（超长、空、编码异常、路径不存在）

每类至少一条，且"不应触发"的用例与"应触发"的同等重要——只测前者会养出一个抢路由的 skill。

## 中文用户专节

规定输入语言、输出语言、文件命名、日期格式。不写这一节时，agent 会在中英之间随机漂移。

## 递进建构

四步各自独立可运行，不必一次做完：`SKILL.md` → `+references/` → `+scripts/` → `+动态上下文`。每加一层才解决上一层留下的具体问题；为层级本身而加层，就是缓存了环境本来查得到的东西。
