# 正反例对比

## 指针（description）

```yaml
# ❌ 一个 branch 写了四遍，且身份描述正文已有
description: 前端UI速查手册。触发词：「skill准则」「skill设计」「skill修改」「skill规范」。

# ❌ 太弱，没写到达条件
description: 处理投资相关的各种事情

# ✅ 领词前置，一个 branch 一个条件，带排除
description:
  雪球博主画像提炼。输入原文+控制台信息，返回完整画像。
  提炼博主画像、更新人物档案时使用；沉淀投资观点与逻辑链走 wiki-refine。
```

## Default stance：把禁令改写成正向目标

三条「绝不」把三个被禁行为逐个搬进上下文；正向表述让 agent 注意力落在要做的事上。

```markdown
# ❌ 否定式（把被禁行为说了一遍）
## 禁止行为
- 绝不修改 pipeline 传入的路径
- 绝不删源文件
- 绝不添加原文无的观点

# ✅ 同一组护栏，落在正向目标上
## 边界
- pipeline 传入的路径只读，产出写到指定输出路径
- 源文件保留原位，需要清理时走删除流程
- 观点只来自原文，原文没有的不写
```

无法正向表述的硬护栏保留禁令，但同时给正向目标：`不合格信号根本写不进去——服务端 `_validateSignal()` 拒收，写入前先过三问`。

## Workflow：每步止于完成判据

```markdown
# ❌ 散文，且没有结束条件
你需要先读文件，然后检查一下字段齐不齐，缺的话就补上，最后写回去。

# ✅ 编号 + 可核查且穷尽的判据
1. 第一步：读取文件，校验 frontmatter。判据：每个必填字段都已点名，缺失项列成清单。
2. 第二步：缺失字段 → 报错停止；完整 → 继续。
3. 第三步：生成输出，写入目标。判据：写回后重读，字段与输出表逐项一致。
```

「检查到位为止」是模糊边界，招致提前收工；「每个必填字段都已点名」可核查且穷尽。

## 阶梯与相关性

```markdown
# ❌ 348 行：原则、规律、模板、示例全堆在主文件
# ✅ 139 行：步骤与领词在正文，细则按 branch 下沉
核心流程在 SKILL.md；指针写法→principles.md；机制→mechanics.md；模板→template.md
```

短不是美德本身，是为了让「这一行还活着吗」查得动。
