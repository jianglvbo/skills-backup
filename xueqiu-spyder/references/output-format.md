# 帖子集输出格式规范

> 由 xueqiu-spyder SKILL.md Output Format 引用（2026-09-26 起 post-fetch 已并入本 skill）。帖子集按 #29 例外流程直接进提炼（投资框架 skill 提炼环节加载），不经粗加工。
> **2026-09-26 feed 模式新增**：多博主帖子集（发布行级 `作者：`）、回复内容块（引用卡结构化）、时间来源标记。

## 字段表

| 字段 | 类型 | 说明 |
|:---|:---|:---|
| title | string | 帖子标题（有 title 字段用 title；无 title 取正文首个完整句子，不硬切字数） |
| text | string | 正文全文（截断帖补全后标记） |
| created_at | string | 发布时间（YYYY年M月D日 HH:MM） |
| form_type | string | **帖子形态：回复 / 短文 / 长文**（客观判定：有"回复 @"/引用块 → 回复；正文 <200 字且无引用块 → 短文；≥200 字或含小标题/分段 → 长文；2026-09-06 起落进摘要行，供提炼零解析读取） |
| retweet_count | int | 转发数 |
| reply_count | int | 回复数 |
| like_count | int | 点赞数 |
| is_pinned | bool | 是否置顶 |
| completeness | string | 全文 / 摘要 |
| post_url | string | 帖子原文链接（`https://xueqiu.com/{xq_id}/{post_id}`） |

## 三件套结构

每帖为 `## N. 标题 + 正文 + 摘要行`，帖间以 `---` 分隔；摘要行标记「全文」或「摘要」，并携带形态与**作者**（2026-09-26 起，多博主帖子集的权威归属）：

```markdown
## 1. {帖子标题}

{正文全文}

> 发布：{YYYY年M月D日 HH:MM}{时间来源标记} | 形态：{回复|短文|长文|专栏} | 作者：{昵称} | 转发 {n} | 回复 {n} | 点赞 {n} | 全文 | [原文](https://xueqiu.com/{xq_id}/{post_id})
```

> 时间来源标记（feed 模式）：详情页验证＝无标记；流内相对时间推算＝`（流内推算）`；「修改于」推算＝`（修改于·推算）`（编辑时间≠首发时间）。user 模式（详情页权威时间）无标记。

## 回复内容块（2026-09-26 新增，feed 模式；**专栏与原帖两种样式**）

转帖引用（引用卡）解析为结构化「回复内容」，置于正文之后、发布行之前——**这是提炼侧 replyTo（被回应者的话）的直接来源**：

**被引是专栏**（文章——replyTo 取标题，导语是截断参考）：
```markdown
> 回复内容·专栏：@{被引作者}《{文章标题}》（{流内时间} · 转发 {n} · 讨论 {n} · 赞 {n}）
> 文章导语（截断）：{流内截断导语}
> 被引原文：https://xueqiu.com/{xq_id}/{post_id}
```

**被引是普通帖子**（卡内文本即被回应者原话，通常完整）：
```markdown
> 回复内容·原帖：@{被引作者}：{被引帖文本}
> 被引原文：https://xueqiu.com/{xq_id}/{post_id}
```

- 被引专栏全文**不随流采集**（流内只有截断导语）；需要全文时凭被引原文链接走专栏例外路径
- **详情页来源的正文已内联引用时省略本块**（防重复）；回复帖（正文以「回复@」开头）不产生本块——其被引内容由正文 `//@` 链承载

## 多博主帖子集（feed 模式）

- frontmatter `author` 记「{关注流|热门流} {N} 位博主」（仅兜底）；**每帖发布行 `作者：` 才是权威归属**，入库按其解析并以 URL uid 仲裁纠正
- 非看板博主的帖子在采集侧即被过滤（关注流缺省开），不入产物

## frontmatter

```markdown
---
title: "雪球帖子采集：{nickname} {YYYY年M月D日}"
source: "https://xueqiu.com/u/{xq_id}"
author: "{nickname}"
date: "{YYYY年M月D日}"
recorded: "{YYYY年M月D日}"
type: "帖子集"
status: "待提炼"
tags: []
---
```

**status 取值（2026-09-09 新增，摘要标记）**：

| 值 | 含义 | 提炼处理 |
|:---|:---|:---|
| `待提炼` | 全部帖子均为「全文」（经详情页验证） | 正常提炼 |
| `待提炼-含摘要` | 含「摘要」帖（详情页风控未补全全文） | **只提炼标「全文」的帖；标「摘要」的一律跳过** |

> 判定以每帖摘要行的 `全文` / `摘要` 标记为准，status 仅作文件级快速提示。采集器与补全器均自动维护该值。

## 铁律

- 每帖必须带 `[原文](https://xueqiu.com/{xq_id}/{post_id})` 链接（画像表原文链接唯一权威来源，framework-rules #35）
- 未经详情页验证不得标「全文」——**user 模式**；**feed 模式**以流内完整性信号为准：流内渲染完整（无展开控件）或流内展开成功＝全文（2026-09-26 实测，DOM 自带截断控件）
- **标「摘要」的帖不可提炼**（内容不完整，2026-09-09 用户确认）：提炼环节只处理标「全文」的帖
- **标题不得截断 markdown 链接**（2026-08-26 教训：`body[:30]` 硬切曾把 `[$中国联通(00762)$](https://xueqiu` 切成残缺 URL）。标题提取：优先正文首个完整句子（仅全角 `。！？` 断句，URL 中半角 `?`/`!` 不作句末）；无完整句子时按链接整体安全截断
- **发布行 `作者：` 与 uid 归属仲裁**（2026-09-26）：多博主帖子集按发布行作者入库，URL uid 与建档雪球号冲突时按 uid 纠正、无法纠正则跳过
