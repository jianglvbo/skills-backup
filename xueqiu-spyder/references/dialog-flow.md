# 雪球对话串采集流程（用户定稿 2026-09-29/30）

适用：采集「博主参与的整套对话」＝回复帖完整问答链 + 被回复原文。
与 feed 流式采集的关系：日常增量仍走 feed（main.py feed）；对话串按需/回溯采集，不替代 feed。

## 定稿流程（四步，全程页面点击，不裸调 API）

1. **主页找回复帖**：博主主页时间线找「回复@某人」帖 → 点正文展开
   - 控件 `a.timeline__expand__control`；页面存在大量隐藏同名模板（offsetWidth=0），只点可见那个；
     做法＝目标项打 `data-zc-exp` 标记后**真点击**（桥的 `click`，CDP Input 域、isTrusted=true）。
     ⚠ 展开成功后同一控件变「收起」，标记判据里必须带「文案含展开」，否则残留检测会误判成没展开
2. **查看对话拿全链**：展开后出现「查看对话」（`a.dialogue__btn`，正文展开后才出现）→ 点开 `.modal.modal__comment` 弹窗，滚动加载 `.comment__item` 至条数稳定
   - 弹窗直接给出根帖→当前回复完整问答链，**这是拿整套对话的最快入口**
   - 链序＝时间升序，平铺、无缩进、无「回复@某人」前缀
3. **引用卡拿被回复原文**：`blockquote.timeline__item__forward`＝被回复原文
   - 卡上可见展开控件点开拿全文；拿不到 → 点卡内「讨论 N」锚点（`a.replay-count`，href=/uid/statusid#comment）进原文页取 `.article__bd`
4. **拿到原文即止**：不翻该原文的其他讨论（用户明确）

## 关键判定与坑（实测）

- **时间线是分页制**：每页 20 条 + `a.pagination__next`「下一页」AJAX（URL 不变）；纯 scrollTo 永远停在 20 条
- **有串/原发分类判据**：条目上 `a.dialogue__btn` 可见＝回复（有串）；否则＝原发（含引用帖）；个别回复雪球不给对话入口（父链不可达）→ 归「未采·无入口」，不算失败
- **「查看对话」≠「查看回复」**：前者无排序无条数（定稿呈现）；最热/最新/最早 tab 属于后者，别搬
- **链首 ≠ 真被讨论帖**：弹窗链首可能只是评论区早期评论；真被讨论帖＝打开回复帖永久链接页，取引用卡上下文锚点（fake-anchor / replay-count 的 href）
- **链根是自己原发帖的串**：被讨论帖指向自己根帖，不是回复卡里引用的外部帖
- **讨论/赞数字不采（2026-09-30 用户定稿）**：只保留「N位达人赞过/作者赞过」标识（`.extend_comment_info`）。原因：拍平文本会把「讨论」标签与「赞」的数字黏连产生二义，索性不采数字

## 文本清洗规则（落库前必做）

- 剥 iconfont 私有区字符 `U+E000–F8FF`（「收起/转发」等实为图标）
- 正文前缀：`^收起?<博主名>(修改于)?`（示例名勿硬编码，按采集目标代入） + 时间（昨天|今天|MM-DD|YYYY-MM-DD HH:MM）· 来自**来源词白名单**（Android|iPhone|iPad|iOS|雪球|Web|Windows|Mac|HarmonyOS…）——禁止 `来自\S+`（贪婪吞掉正文开头「回复@X:」）
- **折叠重复段**：展开态 DOM＝全文＋截断重复段；取首 50 字符为探针、从 60 字符后找二次出现位置截断；再剥尾部「展开⌄」
- 链节点尾部拍平数字：根节点＝讨论数、其余＝赞数（弹窗固定结构）

## 设计动机（2026-09-30 用户实例）

回复帖「雪月霜：是的，最极端就是把所有涨幅全部抹去…本人其实已经开始买入了」提炼时标的解析不出进了待裁决——inline //@ 链被雪球截断一跳，标的那跳（其本人被引用帖开头 `$天齐锂业(SZ002466)$ $赣锋锂业(SZ002460)$`）看不到。对话串采集拿到被回复原文/全链后即可上溯补标。
对应提炼规则（第⑤步，**已实施** 2026-09-30 `1ab49d0`）：提炼侧不走本采集器，直接调 MCP `thread_chain`（传言论 sourceUrl，服务端查链 + 逐节点 $标的$ 候选预解析，语义锚定留给提炼 agent）；回复型言论 subject 解析不出 → 沿链上溯（先紧邻 replyTo、再被讨论帖）→ 命中即挂标免进待决策，继承标的留痕（口径=继承自对话链）；上溯到根仍无标的才进待决策（裁决卡带链上下文）。规则落 investment-framework `references/stock-mention-rules.md`（四）+ `refine-schema.md`。

## 采集器与落库工具

- **采集器 `scripts/xq_dialog_collect.py`**（本 skill 内，ego 通道，前置＝ego lite 开着且已登录雪球）：
  - 时间线模式（缺省）：`--blogger <名> --pages N`，翻页止于 `--stop-before <时间>`（时间感知止损，避免旧帖盲翻）
  - **原帖全量抓取 `--full-root`（2026-10-05 去 goto 化）**：对每条串**真点击引用卡里的被引链接开新标签**，
    在原帖页抓完整正文（保留段落、不截断）+时间（`.article__author time`）+形态+图片 → `root.full`，抓完即关标签；
    落库侧写 post_history `post_kind_code='origin'` 行并回填 `xq_thread.root_ph_id`（同根兄弟串共享同 id）。
    锚点两条形态：普通帖「 · 讨论 N」（href 结尾 `#comment`）、长文引用卡标题链接。
    **必须在每页收尾做**（`_flush_page`）：出了那一页卡上就没锚点了——旧版靠 goto 才敢拖到全场结束。
    与 root_content 脏写事故不矛盾：那里错在回复帖页抓正文，这里抓的是原帖页
  - **关注采集 `--follow`（2026-10-03 关注提炼）**：从雪球关注列表（首页左栏「关注 N」→ /center/#/friends，`.profiles__user`）逐博主跑完整链路；回补点=`--cutoffs` JSON（{uid: YYYY-MM-DD}，由 post_history 最早已采日期生成）或 `--stop-before` 兜底；每位博主独立产物 JSON。**分工（用户定稿）：关注流为主、旧 feed 流备用（首页提炼）**
  - **URL 直达补采已删除（2026-10-02 用户定稿）**：`--urls`/`--keywords` 与搜索点击→详情页那条补采通路整体移除，采集器不再有「给一个 URL 跳进去取」的入口
  - 韧性：错误分类（代码性错误不重启桥）、单条目重试上限 2 次跳过、翻页空转止损；带病完成 `degraded` exit 3（≠失败，产物仍可用）
- **落库 `src/scripts/import-thread.js`**（仓库侧）：采集 JSON → 四表幂等导入（post_history 只补缺、追踪博主正文反查回连不双写）；`root.full` → post_history **origin 行**（blogger_id=NULL 不建博主档案、refine_status=1 不进提炼增量）+ `root_ph_id` 回填；入库校验过才算落库成功
- 老帖判据：先看回复帖时间，超出时间线回溯窗口（≈2.5 天）**就不补采**——裸 URL 直达易触风控，该通路已按定稿移除，别拿翻页去硬追旧帖

## 落库口径（用户定稿 2026-09-30）

- **陌生作者的节点只存对话串展示用**：不进言论体系（statement_* 六表零接触）、不参与加工提炼、**不落 post_history**；正文存在链节点表，作者走轻身份表（xq_thread_author）
- **追踪博主不重复落**：其链节点内容不双写——url 指回 post_history（原始）/statement（提炼后），节点表存 url + 关联即可；两边采集（对话串侧/博主自己时间线侧）靠 post_history url_hash 收敛到同一行
- **「N位达人赞过/作者赞过」标识保留**（节点字段 daren_info）；讨论/赞数字不采
- **原发帖不走对话串采集**：其正文由 feed 例行覆盖；对话串采集只处理回复帖（dialogue__btn 可见），防重复采集
- 链骨架：content_hash（作者+时间+正文）唯一做节点判重；关联表显式存 seq + parent_seq（A 先、B 回 A、C 回 B 的链路）；**一条触发回复＝一行串**（xq_thread.trigger_url 唯一，入库前归一化去 `www.`，e8a5d4c 改——同根不同回复各自成串、共根串共享链节点，不再按「同一对话」合并）；thread_key＝被讨论帖 url 仅作分组参考
- 被讨论帖为陌生作者时：正文快照存串行（root_content），追踪博主则留 NULL 走 url 指回
- **节点 url 回填机制（10-01 用户验收定稿）**：弹窗节点只有评论 id（≠status id，硬拼 404），采集器不凭空造
  url，唯一回填路径＝节点文本反查 post_history 命中（该帖曾被 feed/user 留档）→ 回填 url + post_history_id。
  因此**老帖（早于留档起点）/陌生作者评论节点 url 为空＝设计内**，弹窗「原帖 ↗」按钮缺席但正文照常显示；
  用户拍板维持现状、不为老帖补采（2026-10-01）
- **触发帖未落言论的串**：不挂言论卡（无宿主），只在看板「对话串」菜单页按串显示——用户认可此规则（10-01）
- **单节点串＝雪球弹窗本就无链（10-02 补采实证）**：9 条单节点串逐一重开弹窗仍只有触发帖自己——
  雪球对这类回复不提供对话链（「无对话入口」的变体），不必反复补采；对方原话只存在于**原帖正文的 //@链**
  （时间线 innerText 里常被剥，留档也没有），回应块显示靠**提炼侧 replyTo** 从原帖页面取，弹窗无对方节点属正常
- **回复帖标的 ≠ 被讨论帖的主体（10-02 耀才判例，提炼侧铁律）**：晨曦价投在中烟香港帖下回复贤惠的打新小风扇
  「至少翻倍以上吧……」——对话聊的是**耀才证券**，中烟只是发帖载体；挂标锚定以**对话内容**为准
  （对方原话「大佬耀才看到多少啊」里的耀才），不因帖子在哪个标的的帖下就挂哪个（候选≠结论的实况判例）；
  signal 概括同样要以真标的开头（「耀才证券至少翻倍」而非「中烟至少翻倍」）
- 抓原文前先按 URL check post_history（仅限追踪博主），已留档不重抓
